# Live collaboration audit — 2026-10-22

Scope: source review, deterministic Yjs interleavings, and two independent live browser tabs on a disposable OSIRIS clone. Real team diagrams were not edited. Same-machine tabs do not establish cross-computer latency or mobile/background-tab reliability.

## Confirmed and addressed in this pass

1. **Stale React state republishes unrelated peer entities.** In `pushStateToDoc`, the original node/edge/shape/part/custom-symbol loops compared React values against the current Yjs values, rather than checking what this client changed since its last applied snapshot. Reproduction: B moves from x=300 to x=380 remotely; an unrelated local edit to A republishes B at x=300. The patch skips unchanged local entities across collections and skips IDs that a peer deleted. Explicit deletion and Yjs undo remain supported. Symbol override behavior is untouched.
2. **Remote deletion resurrection.** Delete B remotely, then publish an unrelated local edit to A from a render that still contains B. Before: B is recreated. After: B remains deleted. The guard also covers a stale local modification to the deleted entity.
3. **Shared canvas/SOP rollback.** An unrelated node edit could republish an older canvas size or baseline SOP. These metadata values now publish only when this client changed them relative to its base.
4. **Every remote document edit clears local selection.** Live reproduction: select FTV-1 in tab A, edit FCV-2 label X in tab B, and A immediately shows 0 selected and loses its inspector. Remote refresh now preserves valid component/pipe/shape selections in the active local test context, clearing only references that no longer exist.

Validation: `node scripts/check-collaboration.mjs`, `node scripts/check-planning.mjs`, production build, and live two-tab validation after deployment. The collaboration regression includes core entity collections, remote deletions, shared metadata, new entities, explicit deletion, and undo.

## Live validation of this pass

On the deployed fix, both tabs converged on FCV-2 label X=51 while tab A kept FTV-1 selected. Editing FTV-1 label X in A and then undoing it restored its original 49.47526901323795 value while B's FCV-2 edit remained 51. No production team diagrams were edited. The two tabs shared one network, so this is not a latency or packet-loss benchmark.

## Significant remaining problems

### P1: An older peer can overwrite a live edit during the initial handshake

`projectToDoc` independently seeds each Y.Doc from JSON, creating different CRDT histories. The join handshake exchanges both complete histories. This makes them converge, but convergence does not mean the newer human edit wins. Deterministic reproduction uses client IDs 100 and 200: the first client edits A.x to 222; the late client initializes from the older JSON where A.x=100; exchanging full states converges to 100.

Reproduce with `node scripts/audit-collaboration.mjs`. This is an intentionally failing diagnostic (exit 1), not a passing regression. The stale React patch does not solve this initialization conflict.

### P1: Snapshot persistence has a check-then-write race

`persistNow` checks the stored timestamp, optionally loads and merges the JSON, then `saveProjectDoc` unconditionally upserts the full document. Two clients can both pass the check before either write, then overwrite each other's snapshots. There is no atomic revision comparison. The timestamps are generated by the clients. This is confirmed from source; a destructive production race was not induced. Broadcast delivery may repair some such races, but is not durable conflict protection.

### P1: Same-entity and same-test editing is still coarse

Baseline nodes/edges are whole JSON values in Y.Map, so two users editing different fields of the same component can overwrite one another. Each test configuration is an entire Y.Map value, including its diagram and sequences; two users editing different components inside the same test still compete over that whole configuration. The latter is already documented in `test-planning-review.md`.

### P2: The hot edit path does substantial full-document work

Each drag update compares many JSON entities, broadcasts updates, and peers serialize the document and apply planning state before the editor recomputes derived diagram data. There is no explicit pacing/coalescing for drag document updates. Full-state handshakes grow with Yjs history. These are credible contributors to lag, but this audit does not assign measured milliseconds or throughput to them.

### P2: Saving and connection status are conflated in the UI

The header shows a save indicator and peer count, but the realtime-up callback is empty. A successful snapshot write does not prove another user received an edit. The save completion path also sets saved=true without confirming that the document stayed unchanged while the request was in flight. Outgoing realtime updates are dropped while the channel is not live, relying on later handshakes for recovery.

### P2: Presence lacks editing context

Presence contains user, cursor, and selected IDs, but no test/sequence identifier. Test diagrams reuse component IDs when copied, so collaborators in different configurations can appear to point at the same component even though they are editing different snapshots. Rendering currently displays peer cursors, but does not consume peer selections for component outlines.

## Recommended next pass, in order

1. Persist and reload one canonical Yjs history for each project, with an explicit migration/compatibility boundary for older clients. Do not manufacture independent JSON seed histories on every join.
2. Make durable saves atomic through server revisions or an equivalent transactional path; serialize/retry client save requests and only mark the exact acknowledged state saved.
3. Give each test diagram per-component/per-edge entries, then use field-level shared state for component properties that should merge independently. Preserve current JSON import/export and local test/sequence selection.
4. Pace drag updates, minimize React work for unrelated entities, and make pointer gestures one undo action. Verify long drags, typing during remote edits, concurrent component deletion, and reconnect after missed updates.
5. Show actual connection/reconnecting/unsent states and scope presence to the active configuration. These UI additions should follow Daniel's approval of the plan.

Acceptance matrix: two clients edit different components; different properties on one component; different components in one non-baseline test; join while another client drags; disconnect/reconnect; delete versus move; undo without reverting a peer; persistence reload after concurrent saves; network delay/loss; inactive/background tabs. Require consistent final documents and no unrelated selection loss.

RLS, grants, and shared symbol override semantics are outside this change.
